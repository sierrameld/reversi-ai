# Experiments

This file contains the full data behind the results in the [README](../README.md).

All percentages are **scores**. A win counts 1, a draw counts 0.5.

## Common setup

The same setup was used for every network.

- Positions come from games between two random players (seed 1). Duplicate positions are removed. Each training example is a position from the point of view of the player to move, together with the value the teacher `Minimax(depth)` gives it, from -1 to 1.
- The positions are shuffled (seed 1). 10% are held out to measure the error on positions the network has never seen, the network learns on the rest.
- Initial weights are uniform in ±1/√(number of inputs of the neuron), seed 1. Biases start at 0. `tanh` on every layer.
- Stochastic gradient descent on one example at a time, error `E = (y - t)^2 / 2`, the training set is shuffled before every epoch.
- CPU: Intel i5-11400F.

## Datasets

The positions depend only on the number of games, not on the teacher. The random games are always the same (seed 1), only the target values differ. So 3,000 games give the same 162,327 positions for `Minimax(3)` and `Minimax(6)`, and the positions of 30,000 games are contained in the positions of 80,000 games. Comparisons between teachers on the same number of games are therefore fair.

- **Batch A** (night of 16–17 October). 13 separate networks, 20 epochs each.

## Margin of error

A result over N games is a share of points. For a share near 50%, the 95% margin of error is

```
1.96 × √(0.25 / N)
```

| Games | Margin of error |
|---|---|
| 400 | ±4.9 points |
| 2,000 | ±2.2 points |

When two networks are compared, both results have this error, so the margin for their difference is about √2 times larger. For 2,000 games that is √2 × 2.2 ≈ 3 points. This is where the replacement threshold of 3 points comes from.

There are two kinds of tests.

- **Quick test.** 400 games against each of `Random`, `Minimax(1)` and `Minimax(3)`, 4 random opening moves, seed 1. The margin of error is about ±5%, so this is only a rough guide.

## Findings

All comparisons below use the re-check against `Minimax(3)` where it exists.

- **More positions help, but a shallow teacher has a ceiling.** Runs 5 and 14 both use `Minimax(3)` as the teacher, the same 64-64-32-1 network and a learning rate of 0.01. 40,000 games (run 14, 60 epochs) gave the same result as 20,000 games (run 5, 20 epochs), 34.8% and 34.5% on the re-check.
- **A better teacher needs enough positions.** `Minimax(4)` on 30,000 games (run 15) reached 42.4%, far above `Minimax(3)` on 40,000 games. With the same network, `Minimax(5)` on 40,000 games (run 23, 48.5%) scored higher than `Minimax(4)` on 80,000 games (run 22, 45.4%). But `Minimax(6)` on only 3,000 games (run 19) gave one of the weakest networks (25.6%).
- **The network size has to match the data.** On 1.6 million positions, a wider first hidden layer (run 16, 64-128-32-1) was not better than 64-64-32-1 (run 15). On 4.2 million positions, 64-128-64-1 scored higher than 64-64-32-1 at both checkpoints (runs 22 and 21, 45.4% and 43.2% after 60 epochs, 40.5% and 38.5% after 30), but the difference is below the margin for comparing two networks, so it is a likely trend, not a proven one.
- **Learning rate decay.** After about 40 epochs a constant learning rate of 0.01 gave no further gain. Run 15 scored 42.4% after 40 epochs and 41.9% after 60, run 16 fell from 41.9% after 20 epochs to 39.1% after 60. With decay, the second half of training raised the three candidates by 2.9–4.9 points. Run 21 went from 38.5% to 43.2%, run 22 from 40.5% to 45.4%, run 23 from 45.6% to 48.5%. Batch D has no constant-rate run on the same data, so part of this gain may come from the extra epochs themselves. The direct comparison is batch C, where decay (run 17, 43.1%) beat a constant learning rate of 0.003 (run 18, 39.0%) on the same data by 4.1 points, and reached the strength of the previous final network (run 15, 42.4%) with 20,000 games instead of 30,000.
- **A lower held-out error does not always mean stronger play.** On the same 10,000 games, 64-64-32-1 (run 3) had a clearly lower held-out error than 64-32-16-1 (run 2), 0.0330 and 0.0366, but both played the same in the quick test against `Minimax(3)` (34.8% and 35.2%). A second example is in the control examples below.

### Control examples

Run 20 was planned in advance to show what goes wrong. Run 19 was planned as a comparison (same network as run 21, same positions as run 20) and turned out to be a control example as well. Both use a very deep teacher (`Minimax(6)`) but only 3,000 games, because generating its targets is extremely slow.

- **Best teacher, too few positions** (run 19). Even the best teacher cannot help when there is too little data. 25.6% against `Minimax(3)` on the re-check.
- **Huge network on little data** (run 20, 64-256-256-1, 82,689 parameters). After 90 epochs its error was 0.020 on the training positions and 0.049 on the held-out positions, 2.5 times higher. It started to memorise. After about epoch 45 its training error kept falling (0.025 → 0.020) while the held-out error stopped improving (about 0.048–0.049). Its held-out error is even lower than that of the small network on the same data (0.049 and 0.053), but it plays no better (24.6% and 25.6% on the re-check).

### The quick test is not enough

Twice a network looked best in the 400-game quick test and then fell on the 2,000-game re-check. Run 9 scored 48.0% against `Minimax(3)` in the quick test and 37.9% on the re-check. Run 22 after epoch 60 had the best quick test result against `Minimax(3)` of all networks (52.8%) and 45.4% on the re-check. Most of this was luck. The re-check also uses 6 random opening moves instead of 4, which on average lowers scores by about 2 points. Therefore the final network was chosen only by the re-check.

### Replacement rule

A new network replaces the current one only if it is better on the re-check against `Minimax(3)` by more than the margin of error, about 3 points.

- After batches A–C, run 15 after epoch 40 (42.4%) became the first final network. Run 17 after epoch 40 scored slightly higher (43.1%), but the difference was within the margin of error, so the simpler network with a constant learning rate was chosen.
- After batch D, run 23 after epoch 60 scored 971 points of 2,000 (943 wins, 1,001 losses, 56 draws), 48.5%, which is 6.1 points more. It replaced the previous network. Run 22 (907.5 points, 45.4%) missed the threshold by 1 point. The threshold is the previous network's points plus 3 percentage points of 2,000 games, so 848.5 (823 wins, 1,126 losses, 51 draws) + 60 = 908.5.

The same luck effect also appears in a smaller form after choosing. Run 23 scored 48.5% against `Minimax(3)` on the re-check (seed 2) and 46.6% in the independent tournament (seed 4). The difference is within the margin of error. A small drop is expected, because the best of 11 tested network states was chosen, and the best result is usually slightly raised by luck. On a new seed it moves back towards the real strength.

### Notes

All observations below were only possible because the tournament is recorded in `models/tournament.csv`, one line per game, 30,000 lines in total (15 pairs of 2,000 games). Each line stores the players, colours, random opening, final disc count and seed, so any game can be found, counted and replayed.

- **Repeated games.** Minimax and the neural player are deterministic, so two of them can only play different games if the openings differ. After 6 random moves there are 7,092 different positions, so some openings repeat by chance. In the first tournament (seed 3), about 130 of 2,000 games between `Minimax(3)` and the network were exact repeats (158 in the seed 4 tournament). This widens the margin of error from ±2.2% to about ±2.3% and does not change any conclusion. Games with the random player never repeat.
- **Colour.** Every player scores about 1–3 points better with white than with black (from 0.8 for Random to 2.8 for the network). The current network scores 62.3% with black and 65.1% with white. Colours are split equally in every pair, so the tables are not affected.
- **Random wins against minimax.** The random player wins against `Minimax(4)` in 0.3% of games. These are rare mistakes of a search with limited depth and a hand-made evaluation, which show up a few times in 2,000 games. In the seed 4 tournament it won 6 games, one of them clearly (47:17, opening d3 c3 f5 d2 b2 g6). These games can be replayed from `models/tournament.csv` for later analysis.
